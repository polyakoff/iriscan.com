Data Portability & Interoperability

Customers and users of biometric technologies require a solution to the problem of biometric data interoperability. Typically, systems have been created to link other systems using a specific format. With the need to communicate with different regional and international firms, the design's limitations became apparent.

The requirement to communicate with multiple authorities was exacerbated by the fact that each external agency supported and, thus, exchanged a variety of generations of data with its own variation. Iriscan provided its BDI(Biometric data interchange) to manage the conversion between the native formats of the external systems for total integration.

Iriscan facilitates compliance with GDPR and other relevant data protection standards by allowing enterprises to examine, store, and when requested provide auditable access to their biometric data. Many biometric data formats store personally identifiable data in the file itself.

Enterprises can be assured that data is stored in a consistent format and that legacy data does not contain personally identifiably data artifacts ensuring full compliance with privacy laws and regulations.

Right to data portability

Iris records: ISO/IEC 19794-6

Iris images travel between systems in ISO/IEC 19794-6 records. A record starts with a general header (the format identifier IIR, the version and the number of irises) and then holds one representation per eye: capture date and time, the capture device, quality scores, the eye label, the image type and the image itself with its size and compression. Because the image is kept rather than a vendor template, any matcher can enroll from it again, which is what makes a register portable.

The 2011 edition added compact image types, cropped and cropped-and-masked, that keep an iris image small enough for a smart card or a slow link while it stays usable for matching. Our open-source iris recognition SDK reads and writes these records:

val record = sdk.io().readRecord(bytes) as IsoRecord19794_6   // also reads 19794-2
val eye = record.data.first()                                 // header + image of one iris
println("${eye.header.eyeLabel}, ${eye.header.imageType}")
val out = sdk.io().writeRecord(record)

ISO/IEC 19794-6 vs 39794-6

ISO/IEC 39794-6 is the successor. It carries the same kind of data, but encodes it in an extensible format (ASN.1 binary or XML), so new fields can be added later without breaking older readers, and it fixes ambiguities of the fixed binary layout. ICAO is moving travel documents to the 39794 series, and new procurements increasingly ask for it. Most deployed registers still hold 19794 data, so a migration usually means converting records in bulk while keeping the images untouched. We do these conversions for iris, fingerprint and face data, on your premises or in the cloud.
